A 3D survivors-like mobile game entry in The Walking Dead universe released for iOS and Android. Many popular characters from the series are available as survivors within the game with their own weapon type, skills, and upgrades. Gameplay is typical of the genre, but it features reloading and building mechanics, and the available upgrades change based on which group of survivors is brought into gameplay. But several alternate game modes greatly change the gameplay, and many out-of-gameplay systems offer ways to increase the survivors' power and stats. A loose storyline can also be followed as players navigate through missions in familiar locales and recruit more survivors to the cause. I joined this project's team of around 10 to 15 members midway through development as a supporting Unity engineer and helped push the game towards launch and post-launch updates.

My main role on the team was meta-systems and gameplay developer, and I shipped end-to-end over 8 major live-service features focused on progression, retention, and monetization. Some of the most prominent features I implemented were the quests, login streak, and season pass systems. Since the team had a history of similar games, this feature work started as a task to port the existing systems from previous games and integrate them into the project's codebase. These tasks allowed me to get a good grasp of this project's inner workings, and each came with additional requests for elements new to this game. Over time, I moved on to building more systems from the ground up, creating the game's dialogue system and The Bar. The Bar was a monetization system that included daily, weekly, and monthly IAP bundles, a currency received for each bundle purchased, and an event gacha that used that currency for pulls from a rotating set of items. I also had the chance to work on the gameplay side of the code, through some of these features and through an alternate Survivor Trials game mode. The trials mode is a challenge mode for replaying previous campaign levels with varying difficulty modifiers that could affect player or enemy stats or prevent helpful items like health drops from appearing.

Many of the features I developed brought challenges from building a live-service game, with players in different time zones, players updating to new features with existing data, and systems that could be updated at runtime with a server fetch. The main skills and experience I gained from this project came from managing these challenges. I used server-authoritative strategies to set specific timed events and prevent player cheating. I managed player save data carefully and performed migrations when updating player data from previous game versions. I built features that can have their data, assets, and schedule configured remotely, so they can be managed outside of the game engine. Following the project conventions, I also gained more experience with unit testing, reactive programming, and mobile performance awareness. Additionally, throughout my work on this project, I learned how to use AI coding assistant tools well while still knowing how the code I was pushing functioned.

The project workflow was Agile and sectioned into 1-2 week sprints with code reviews and an in-depth QA step before any feature was finalized. This worked well for me and the team as a whole, and together with proper documentation and realistic expectations for the deadline, the launch in July 2026 went very smoothly and was well received. At release, the game had over 60 levels, multiple bosses, a few additional game modes, and over 10 survivors with plenty of ways to level up and increase power. Post-launch updates focused on adding more ways to play, more systems to keep players around, and more content in general. The season pass system I had worked on remained the game's top-selling feature, but as the number of players and the money spent within the game were waning, I worked on The Bar system, which offered better low-cost IAPs and rewarded players further for their purchases. Finishing The Bar system at that point proved successful, as a spike in players and spend, similar to the spike from a new season at the start of each month, was tracked once it went live. Despite this, at the time I left the project, the overall outlook was still that the game was not hitting its desired metrics and bigger changes would be needed to reach them.

Challenges:

  • Creating live-ops features that work for all players across a variety of conditions
  • Updating code ported from a previous game to match this project's design patterns and integrate its systems
  • Coordinating work on important features across a large time zone difference efficiently
  • Delivering on a high level of polish with short feature timelines

What I did well:

  • Owned and shipped over 8 major features end-to-end with minimal bugs once live for players
  • Crafted unit tests and developer cheats for comprehensive and convenient testing before releasing each feature
  • Faithfully assembled working and responsive UI menus from designer mock-ups with added animations and VFX
  • Tested performance in editor and on both Android and iOS devices to reduce CPU and memory load in gameplay hot paths

What I would change/improve:

  • Give more time for designers to work with developers to fully close gaps in the technical documentation or grant more freedom for personal fixes/changes when implementing a feature
  • Allow for continued work on released features in the schedule for a higher level of completion and polish or additional time for the feature development deadlines
  • Manage the monetization and economy in a more player-friendly way with less in-game popups, purchasable offers, and difficulty to get new survivors while maintaining a smaller number of high value ways to spend to get ahead
  • Develop features with confidence in their game design and a more defined roadmap for the future updates instead of looking to replicate other similar games in the market and follow data trends
